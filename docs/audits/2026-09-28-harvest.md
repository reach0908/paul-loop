### paul-loop에 대한 해석

- **effort:** ship-flow agent와 skill은 model·effort를 고정하지 않고 세션 설정을 따른다. 따라서 모델 출시에 따른 effort 조정은 plugin 코드가 아니라 사용자·host 설정의 문제다. Opus 5.5 가이드대로라면 `xhigh`를 기본값으로 쓰는 설정은 측정 대상이다.
- **테스트 범위:** Fable 5.1과 OpenAI의 테스트 범위 지침은 [tdd skill](../../tools/ship-flow/skills/tdd/SKILL.md)의 기존 원칙(구현을 되풀이하는 tautological test 금지, 핵심 경로 우선, 실패를 재현하는 최소 회귀 검사)과 대체로 일치한다. 남은 질문은 작은 가역적 변경까지 TDD 경로로 보내는 라우팅이며, 이는 09-22의 P1 라우팅 항목과 같다.
- **완료 판정:** "text-only end_turn은 완료 증거가 아니다"와 "통과 후 새 근거 없이 검증을 넓히지 말라"는 loop-engine의 결정론적 verdict와 bounded retry 계약을 지지한다. 모델 자기보고를 완료 판정에 쓰지 않는 현재 경계를 유지한다.
- **안전 수치:** system card의 부정행위·거절 수치는 특정 평가 조건의 결과이며, 저장소 verifier를 느슨하게 할 근거가 아니다.

## 4. Aside CLI 1.26.916 사용 메모

로컬에 1.26.717 → 1.26.916 변경 내역이 없어 정확한 차이는 알 수 없다. 이번 사용에서 확인한 점만 적는다.

- `--account u1`로 기본 프로필을 바꾸지 않고 Profile 1에서 실행할 수 있다. `session list --account u1`, `session steer`/`queue`/`resume`으로 실행 중 확인·방향 수정이 가능하다.
- Claude Code에 연결된 Aside MCP의 `exec`에는 account·effort 인자가 없다. Profile 1 조사는 CLI로 실행해야 한다.
- CLI 세션은 기본 ephemeral이고, `exec`는 보고서를 `~/.aside/u/1/sessions/<날짜>_<세션>/artifacts/`에 남긴다. 세션 ID 기록만으로 재확인을 보장할 수 없으므로 원시 출력과 보고서를 즉시 로컬에 보관했다.
- Aside 보고서에서 출시일 오류(Astra), 모델 간 지침 오귀속(Astra의 skill 민감도를 Sol에 연결), 관련 지침 누락(테스트 범위)이 나왔다. 수치 자체의 오류는 없었다. 원문 재확인 단계는 계속 필요하다.
